### P1 protocol details that must be fixed before operational adoption

The proposed GitHub decision path is an authenticated fresh GET of `/repos/{owner}/{repository}/pulls/{pull_number}/reviews/{review_id}` with the exact retained body Ref, selected PR commit, `APPROVED` state and stable numeric principal. Policy must be reviewed by a principal in the independently bootstrapped root allowlist; session permissions must be a subset of policy; gate and bundle permissions must be a subset of session. Every call re-fetches all ancestors. Edited, dismissed, missing, redirected, cached, stale or unreachable reviews refuse. GitHub author-review restrictions require an actual PR author distinct from its reviewer; this packet creates no PR, review or credential. The production issuer and endpoint are implemented transport facts. The repository and root-reviewer set are selected offline above; no live grant, independent bootstrap enrollment or supported non-GitHub receipt provider exists.

**Owner-delegated GitHub review-receipt mapping, inactive until implemented:** set `authorityReceipt.issuer` to `https://api.github.com`; constrain `authorityReceipt.uri` to the exact credential-free `https://api.github.com/repos/{owner}/{repository}/pulls/{positive-pr}/reviews/{positive-review-id}` locator in the pinned repository, without query or fragment; set `decisionId` to that decimal review ID and `sha256` to the exact retained UTF-8 review body bytes. The adapter must authenticate the fresh API response and bind its current reviewer, state, body, PR commit, role, subject capture/manifest Ref, decision, reasons, time, expiry and full scope to the disposition. A valid digest or retained body alone is insufficient. The body-to-disposition mapping and reason fields require a versioned approved schema; the existing GitHub body schemas cannot be silently reinterpreted as the proposed disposition/v1 receipt.

For any non-GitHub execution, target, session or custody receipt, the **candidate minimum protocol** is a versioned immutable payload signed or authenticated by the selected issuer over exact bytes, containing receipt ID, issuer/key ID, audience/action, stable subject principal, exact subject Ref/hash/length, profile/workload/target/session/tenant/source scope, issuance/expiry and any decision/reasons. Retrieval must pin one approved origin and independently verify the payload and current issuer/key/receipt/grant status. The actual algorithm, public-key fingerprints or service identity, issuer endpoints, status-proof wire format and principal mapping are unregistered and prohibited for operational use today. No formatter, URL or hash created by Memories can appoint that root.

The owner-delegated choice makes GitHub review IDs **authoritative for review decisions only**. Before operational use, the approved adapter must define how each disposition `authorityReceipt` resolves to exactly one review, its body Ref and `decisionId`, and how current role/session/key revocation and later review supersession are checked. GitHub's present adapter checks only the bound review IDs, not later unbound reviews or branch-protection state. Producer-execution, target and custody receipts need their own selected authentic source regardless. The bundle review body has one `sourceCommit`, while the proposed manifest permits different full source commits per gate; Security and the Deployment Adapter Developer must bind that bundle commit to the exact assembler/manifest revision and retain every gate-specific source commit inside the manifest. No historical execution can be authenticated by a later reviewer assertion. See [authority-and-sessions.md](authority-and-sessions.md) and [schemas.md](schemas.md).
