## What Went Well

1. **Consume-only contract discipline held across six stories.**
   Every surface traces each rendered value back to a named `Contracts.V1` Evidence Packet field. The team built per-family traceability tables (contract source, FrontComposer reuse point, authorization source, localization key, unavailable fallback) so "is this safe to render?" had an auditable answer. No parallel web evidence vocabulary was invented.

2. **Tenant isolation and redaction were treated as one security contract, not a UI nicety.**
   Visible text, accessible names, tooltips, copied/exported text, diagnostics, logs, snapshots, and even DOM `data-*` attributes all share one sanitization path. Story 17.3's review caught a real leak — `MemoriesContextNavigation` wrote a raw return route into `data-return-route` while the visible label was sanitized — and the fix plus regression test (`Navigation_SensitiveReturnRoute_IsRedactedInDataAttribute`) hardened the whole pattern.

3. **Fail-closed handling of unknown and future contract values.**
   Unknown activity types, ingestion stages, health checks, benchmark metadata, MCP fields, expansion handles, and role-density settings render as explicit unavailable/disabled states with safe explanations — never as a successful empty result. This kept honest contract gaps (timestamps, NDCG@10, ingestion taxonomy) visible instead of silently swallowed.

4. **Shared infrastructure paid for itself.**
   `MemoriesLensShell` (with `LensShellViewModel`/`LensShellMapper`) let all five role lenses inherit context-preservation, role-density safety, and return-path logic instead of re-implementing it. The `RecoveryDisplay.SeveritySlot` helper extracted a switch that had been copy-pasted across five lens `.razor` files. `RecoveryStateMapper` kept business logic out of Razor entirely.

5. **State precedence was made deterministic and side-channel safe.**
   The unauthorized-outranks-all ladder (`unauthorized > missing-source/schema-mismatch > redacted/compressed > degraded/partial > supported`) is implemented and tested by exhaustive state×isolation matrices (e.g. `Map_EveryStateAndIsolationCombination_IsDeterministicAndSideChannelSafe`). Inaccessible states never reveal whether evidence exists beyond the authorization boundary.

6. **Conformance hardening closed the epic as a gate, not a memo.**
   Story 17.6 replaced raw markup and legacy tokens with Fluent primitives (`FluentMessageBar`, `FluentLabel` + `Weight`, `--colorNeutralStroke1`) and stood up a source-scanning conformance suite (`Epic17ConformanceAllowlist` + `Epic17ConformanceTests` + hardening/remediation tests). A future maintainer cannot add an unclassified `.razor`/`.razor.css` file or an unallowlisted legacy token without the suite failing.

7. **Accessibility and localization were present from story one, not bolted on.**
   Component-level a11y assertions (accessible names, heading order, focus contracts, live-region pairings, no hover-only behaviour, non-colour signalling) and EN/FR resource parity tests existed from 17.1 onward — exactly what Murat asked for in the Epic 16 retro.

8. **Review pressure measurably improved the code before close.**
   Story 17.1's review applied 26 patches (3 critical, 9 major, 14 minor) and recorded 18 deferred items. Critical fixes included an authorization data leak in Source/Graph/Axis components, a hard-coded `FreshnessLabel()` masquerading as contract truth, and loading/error states hijacking the contract `PendingExpansion`/`Degraded` enums. The epic got stronger story over story.

## Challenges

1. **The host-less RCL constraint capped what "validated" can mean.**
   `Hexalith.Memories.Web` has no `Program.cs`, no `@page`, no runnable host. All validation is component-specimen level via bUnit + `Hexalith.FrontComposer.Testing`. Real-browser rendering, Playwright/axe scanning, forced-colors and reduced-motion emulation, zoom/reflow, touch-target sizing, and at least one manual screen-reader pass are all deferred and recorded as fail-closed gaps in `Epic17ValidationInventory.Gaps`. No story has yet closed them. This is the single largest carry-forward.

2. **Story 2.7 (Evidence Packet Contract Mapping) was `review`, not `done`, for the entire epic — and still is.**
   Every story consumed the Evidence Packet as a fixture-backed dependency. Contract fields the mapper does not yet expose — activity timestamps (so Case Activity Trail orders by source rank with an explicit "timestamps unavailable" note), NDCG@10 scoring and per-query breakdowns, ingestion-stage taxonomy, MCP tool/request schema fields, operator-health freshness/last-checked metadata, and the role-authorization model — were rendered as honest unavailable boundaries. These remain blocked on 2.7 reaching `done`.

3. **Story 17.1 predated the strict Fluent V5-only boundary.**
   It shipped raw markup, scoped CSS, and non-Fluent-2 tokens that later had to be audited and remediated under 17.6. The team correctly forbade extending that pattern into 17.2–17.5, but it meant the first story carried debt the last story had to pay down.

4. **Documentation drift between dev, QA, and review phases recurred.**
   Across 17.3, 17.4, 17.5, and 17.6, reviews repeatedly found File List omissions and stale test counts (e.g. `407/407` vs the real `453/453`; `460/460` vs `475/475`) because QA gap-closure passes added tests after the Dev Agent Record was written. Every instance was reconciled by review, but the pattern is a process cost, not a code defect.

5. **Sandbox test infrastructure required a standing workaround.**
   `dotnet test` aborts locally on a VSTest TCP listener (`SocketException (13): Permission denied`). The team ran the xUnit v3 in-process runner directly with `DiffEngine_Disabled=true`. This matches the known sandbox limitation and should be documented in dev notes from day one of any web story.

6. **Repo-wide EOL inconsistency caused whole-file diff churn.**
   LF-vs-CRLF mismatches (no root `.gitattributes`) inflated several `.razor`/`.razor.css` changes to whole-file rewrites. The team kept LF (the repo-dominant convention, ~99 LF / ~23 CRLF in the Web RCL) so the `git diff --check` gate stayed green, and explicitly scoped repo-wide normalization out.

7. **MCP Fluent UI documentation diverged from the pinned package.**
   The Fluent UI MCP docs target versions (`5.0.0.26098`, `5.0.0.26139`) incompatible with the locally pinned `5.0.0-rc.3-26138.1`. Local submodule code and tests were treated as authoritative throughout — a caution worth carrying into any future web work.

8. **Several capabilities are deferred architectural decisions, not bugs.**
   Command-palette scope (global vs page vs role), browser-refresh persistence of interaction state, mobile grid/timeline transformation strategy, the role-based authorization model, benchmark visualization style, and final lens navigation IA are all explicitly named as deferred and awaiting product/architecture approval.

## Significant Discoveries

1. **A component library is not a validated product surface.**
   The host-less RCL means every "works at 360/768/1024/1440px, keyboard-reachable, screen-reader-usable" claim is currently a component-specimen claim. Promoting Epic 17 to a real product surface requires a runnable host (or specimen app) and at least one manual screen-reader pass. This boundary was not obvious at planning time and forced an active re-scope in 17.5.

2. **Consume-only is an enforcement layer, not a guideline.**
   Treating the Evidence Packet contract as read-only and failing closed on unknown values is what kept five role lenses and seven interaction families from quietly inventing trust semantics. The traceability tables and the conformance allowlist are the mechanisms that make the boundary auditable.

3. **The Evidence Packet contract (Story 2.7) is the real upstream dependency for any future web richness.**
   Timestamps, NDCG@10, ingestion taxonomy, MCP schema fields, and operator freshness metadata are all gated on 2.7. Until 2.7 is `done`, the web surface can only render what the current contract exposes — correctly, but partially.

4. **Fail-closed registers beat prose documentation for conformance.**
   The typed `Epic17ConformanceAllowlist` (six required fields per entry, guarded by tests) and `Epic17ValidationInventory.Gaps` (owner/severity/waiver/disposition per gap) prevented drift in a way a free-text markdown file could not. A maintainer cannot silently miss an entry; the suite fails.

5. **Legacy token detection is unsafe to automate without an explicit forbidden-pattern allowlist.**
   An early automated audit in 17.6 wrongly reported "no legacy tokens" while `*-rest`/FAST tokens were present. Pairing automation with a named-pattern cross-check (`--type-ramp-*`, `--neutral-fill-*`, `--palette-*`, `*-rest`) is what caught the real violations.

## Team Agreements

- The web layer stays consume-only over `Contracts.V1`; it invents no evidence, confidence, state, or recovery semantics.
- Unknown or future contract values fail closed (unavailable/disabled with a safe explanation), never as a silent empty result.
- Redaction and tenant scope are one security contract across visible text, accessible names, copy/export, diagnostics, logs, snapshots, and DOM attributes.
- FrontComposer and Fluent UI Blazor V5 primitives are used before any raw markup/CSS; exceptions require a typed conformance-allowlist entry with a removal condition.
- The Fluent UI version stays centrally pinned and aligned with the FrontComposer submodule; MCP documentation examples are not copied blindly against the pinned prerelease.
- "Validated" for a host-less RCL means component-specimen validated; product-surface claims require a runnable host and a manual screen-reader pass.
- Deferred items and architectural decisions stay structured with owners and reopen/removal conditions.
- Sprint-status epic rows are updated to `done` when all stories are `done` and the retro is complete.
