# Current UI implementation evidence extract

## Scope and authority

- This is implementation evidence for the UX migration, not a replacement for the UX spines. It covers the current `Hexalith.Memories.Web` Razor Class Library (RCL), its Epic 17 component/specimen tests, and the FrontComposer sources whose contracts a future product host inherits.
- The canonical UI input is `EvidencePacket`, a cross-surface contract shared by CLI, MCP, diagnostics, and UI consumers; it owns scope, result, ranked sources, evidence/axes, graph, state, omitted details, recovery, and metadata. The UI projects that contract rather than inventing a second view-domain payload. (`src/Hexalith.Memories.Contracts/V1/EvidencePacket.cs:10-29`)
- The web project explicitly describes itself as an internal, non-packable building block for a future Evidence Cockpit with no product host, and references Memories Contracts, FrontComposer Contracts/Shell, and Fluent UI. (`src/Hexalith.Memories.Web/Hexalith.Memories.Web.csproj:1-20`)

### Ownership that is not implemented by Memories components

- **Product-host ownership remains unimplemented:** activation/route registration, authorization and active-tenant lifecycle, packet retrieval, command/navigation dispatch, focus restoration across real routes, and live notification integration. The component APIs stop at callbacks; the specimen merely records those callbacks in a string. (`src/Hexalith.Memories.Web/Components/Evidence/MemoriesEvidenceCockpit.razor:118-123`; `tests/Hexalith.Memories.Web.SpecimenHost/Components/Pages/Epic17SpecimenSurface.razor:105-193`)
- **FrontComposer owns application chrome and page structure:** `FrontComposerShell`, `FrontComposerNavigation`, `FcPageLayout`, `FcPageHeader`, and `FcPageToolbar`. No current Memories RCL component composes those page/shell primitives; its only direct `Fc*` usages are `FcStatusBadge`, `FcFilterSummary`, and `FcDestructiveConfirmationDialog`, as the source classifications demonstrate. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ConformanceAllowlist.cs:95-145`)
- **Local component layout versus page measure needs an activation decision:** the cockpit currently caps its own grid at `72rem`; FrontComposer says full-width is the page default and constrained measure is an explicit `FcPageLayout` choice. Treat the `72rem` rule as component-local only, or remove/reconcile it when a real Evidence Cockpit page chooses its page measure. (`src/Hexalith.Memories.Web/Components/Evidence/MemoriesEvidenceCockpit.razor.css:8-12`; `references/Hexalith.FrontComposer/src/Hexalith.FrontComposer.Contracts/Rendering/FcPageLayoutMode.cs:7-22`)

## Inherited FrontComposer layout and accessibility contracts

These are contracts a production Memories surface gains only when mounted in the FrontComposer host; the standalone specimen does not prove their integration.

- `FrontComposerShell` is the adopter's `MainLayout` wrapper. It provides skip-to-content and conditional skip-to-navigation links, a focusable shell root with global key handling, and layout/content-label coordinators. (`references/Hexalith.FrontComposer/src/Hexalith.FrontComposer.Shell/Components/Layout/FrontComposerShell.razor:16-22`, `:31-52`)
- The shell owns the single application `banner`, automatic navigation, breakpoint/theme/density behavior, the single focus-targetable `main` landmark, connection/pending-command summaries, footer, and Fluent providers. Memories pages must not add competing app landmarks or recreate that chrome. (`references/Hexalith.FrontComposer/src/Hexalith.FrontComposer.Shell/Components/Layout/FrontComposerShell.razor:53-153`, `:155-185`)
- `FrontComposerNavigation` owns a labelled `navigation` landmark, enabled/disabled navigation entries with readable reasons, `aria-current`, focusable tiles, and contextual menus. Routes conventionally derive from bounded context/projection unless the adopter overrides the shell slot. (`references/Hexalith.FrontComposer/src/Hexalith.FrontComposer.Shell/Components/Layout/FrontComposerNavigation.razor:22-39`, `:56-70`, `:88-104`, `:141-185`; `references/Hexalith.FrontComposer/src/Hexalith.FrontComposer.Shell/Components/Layout/FrontComposerNavigation.razor.cs:24-38`)

## Accordion conformance: evidence and gaps

The repository UX baseline requires exactly one `FluentAccordion` when a page/dialog/detail panel contains two or more sibling titled content sections; page title, breadcrumb, toolbar, navigation, and a lone primary section stay outside; a primary section placed among siblings is expanded by default. (`references/Hexalith.AI.Tools/hexalith-ux-instructions.md:41-51`)

### Proven conformance

- `MemoriesEvidenceCockpit` uses exactly one multi-expand `FluentAccordion` with `HeadingLevel="2"`. It contains the five sibling content items `Evidence`, `Recovery and feedback`, `Sources`, `Retrieval axes`, and `Graph context`. Scope Header and Trust Strip remain outside it. (`src/Hexalith.Memories.Web/Components/Evidence/MemoriesEvidenceCockpit.razor:4-9`, `:53-98`)
- Primary Evidence and Recovery are initially expanded; Sources, Retrieval axes, and Graph context are initially collapsed. User collapse state for both initially expanded items survives parent rerenders. (`src/Hexalith.Memories.Web/Components/Evidence/MemoriesEvidenceCockpit.razor:56-96`, `:131-132`; `tests/Hexalith.Memories.Web.Tests/Components/Evidence/EvidenceCockpitTests.cs:44-60`, `:72-100`)
- Loading and error variants render no accordion or subordinate evidence detail, avoiding empty sibling panels. (`tests/Hexalith.Memories.Web.Tests/Components/Evidence/EvidenceCockpitTests.cs:138-177`)
- Rendered-DOM tests pin current V5 `Header`, `Expanded`, `ExpandMode.Multi`, and heading-level behavior across representative packet states. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ConformanceRemediationTests.cs:41-54`; `tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17AccessibilitySweepTests.cs:187-206`)
- The Agent Packet Inspector's native `details/summary/pre` is explicitly limited to one secondary sanitized-JSON disclosure, not sibling page sections; the allowlist requires its removal when a Fluent inline disclosure/code primitive exists. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ConformanceAllowlist.cs:273-297`)

### Gaps / activation conditions

- Conformance is proven for the **cockpit component**, not a production page. There is no current `FrontComposerShell` + `FcPageHeader` + `FcPageToolbar` + `FcPageLayout` composition demonstrating that app chrome stays outside the accordion.
- The fail-closed source suite classifies every RCL file and guards controls/tokens/semantic exceptions, but the generic suite does not scan future product pages for “two or more sibling titled sections.” The explicit accordion assertions target `MemoriesEvidenceCockpit`. A future page/dialog/detail wrapper therefore needs its own structural accordion test. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ConformanceTests.cs:30-50`, `:73-176`; `tests/Hexalith.Memories.Web.Tests/Components/Evidence/EvidenceCockpitTests.cs:44-60`)
- Do not promote the Inspector's native disclosure into a reusable page-section precedent; its exception is narrowly diagnostic and conditional. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ConformanceAllowlist.cs:273-297`)

## Why this is a conformance specimen, not an activated product surface

- The RCL says it is a future internal building block, has `IsPackable=false`, and contains no executable product host. (`src/Hexalith.Memories.Web/Hexalith.Memories.Web.csproj:1-10`)
- A later standalone host exists only under `tests/`; its manifest calls `/__memories/specimens` a **non-product route prefix** and lists fixture-backed routes for all 19 components. (`tests/Hexalith.Memories.Web.Specimens/Epic17SpecimenManifest.cs:8-17`, `:19-41`)
- The host is itself non-packable and references only the specimen fixture project and the RCL; startup redirects `/` to the specimen prefix and registers Fluent services. (`tests/Hexalith.Memories.Web.SpecimenHost/Hexalith.Memories.Web.SpecimenHost.csproj:1-12`; `tests/Hexalith.Memories.Web.SpecimenHost/Program.cs:10-25`)
- Its app is a minimal test document/router, not `FrontComposerShell`; each route uses a raw test-only `main`, selects one fixture-backed component, and writes interactions to `_callbackLog` instead of dispatching domain work or navigation. (`tests/Hexalith.Memories.Web.SpecimenHost/Components/App.razor:3-17`; `tests/Hexalith.Memories.Web.SpecimenHost/Components/Pages/Epic17SpecimenSurface.razor:1-103`, `:105-193`)
- The inventory test is intentionally fail-closed: every surface must claim `component-specimen`, every route must use the non-product prefix, and the suite explicitly rejects any `product-route` validation claim. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17InventoryTests.cs:20-73`)
- Browser evidence is bounded to the non-product specimen. Full product activation still requires product-route testing, manual screen-reader/focus work, target-device touch validation, a broader browser matrix, and disposition of current axe-incomplete, sub-44px target, and data-heavy overflow findings. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ValidationInventory.cs:114-158`, `:159-210`)
- Responsive tests prove information parity at component level (trust fields remain reachable and compact grid overflow has disclosure), not true product-page behavior at the target widths; the test documentation states the boundary. (`tests/Hexalith.Memories.Web.Tests/Components/Validation/Epic17ResponsiveParityTests.cs:26-32`, `:65-99`)

## Migration implications

1. Preserve all 19 exact component names as the current implementation vocabulary; use the unprefixed UX names as conceptual/copy labels, not alternate code symbols.
2. Treat `EvidencePacket` as the data boundary and keep Memories components projection/validation/intent-only.
3. Specify the future product IA in terms of FrontComposer-owned shell/page/navigation/toolbar/layout contracts, then place the current Memories components inside those surfaces.
4. Record the Evidence Cockpit accordion behavior as normative current evidence. Record the specimen routes, fixture shell, callback log, and raw test-host layout only as validation machinery—not product UX.
5. Carry the product-host, live AT/focus, cross-browser, touch-target, overflow, and axe-incomplete items as open activation gates; do not convert the specimen's browser evidence into a release claim.
