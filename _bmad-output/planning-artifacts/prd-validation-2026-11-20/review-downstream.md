# Downstream PRD handoff review

**Revision required.** The Phase 1 no-go and the 34.33 → 34.1 dependency agree across the current documents. Phase 1.5 gate L1 cannot be scored as written. Several instructions still give implementers different outcomes for the same request.

## Current PRD findings

- **[Critical]** L1 has no relevance labels for its own topics (§ PRD lines 200–205) — The protocol excludes the L1 topics from G1 labelling, then asks the frozen G1 labels to score those topics. It permits more than ten topics but specifies an eight-of-ten threshold. Epic planning reproduces both problems at `epics.md:278`. *Fix:* Freeze a separately labelled L1 holdout before evaluation, define the relevant grade, and choose exactly ten topics with eight passing or an explicit fraction for every allowed set size.
- **[High]** G2 can pass tenant retargeting that FR44 rejects (§ PRD lines 402, 1068, 1152) — The NFR8 test accepts a successful response scoped to tenant A when the caller explicitly requested tenant B. Journey 5 and FR44 require denial. The UX likewise rejects a claim mismatch before retrieval at `ux-designs/ux-memories-2026-09-12/EXPERIENCE.md:224`. *Fix:* Require a tenant-mismatch error and zero restricted output for an explicit conflict. Separate any permitted request with omitted scope from malformed or conflicting scope.
- **[High]** The shared CLI transport promises a delegated caller the Gateway does not carry (§ PRD lines 592, 764–769, 1085, 1154) — NFR10 extends bearer authority across CLI, MCP and internal hops without identifying which transport supports delegation. AD-5 distinguishes native and compatibility bearer paths from the shared Gateway’s workload authority and requires independently proven user authorization before enrollment (`ARCHITECTURE-SPINE.md:144`). *Fix:* State which transports preserve a delegated subject, how granted workloads are authorized, and the admission or refusal condition for a target operation that needs an end user. Apply the same distinction to the addendum at line 63.
- **[High]** The target CLI journeys ask callers to choose durable identifiers (§ PRD lines 394–402, 478–490) — Journey 5 supplies a descriptive tenant ID at creation and Journey 9 creates a case with a chosen slug. AD-23 specifies a platform-issued opaque tenant ID and a case ULID (`ARCHITECTURE-SPINE.md:301–310`). Story 34.52 explicitly refuses a chosen tenant ID (`epics.md:8890–8921`). *Fix:* Ask for a display name, capture the returned ID, and reuse it through verification, ingestion, search and denial examples.
- **[High]** The rule for combining G1 reviewers’ grades is missing (§ PRD lines 170–178) — The steward, reviewer count, pairwise agreement threshold, freeze and scoring metric are specified. Two teams can meet those requirements and compute different NDCG scores by combining the three grades differently. The pending label/run work at `epics.md:6352` supplies no aggregation rule. *Fix:* Before labelling, freeze the ordinal relevance scale and how abstentions, ties and reviewer disagreements produce the single per-topic/per-unit grade used by the scorer.
- **[Medium]** The delivery register attributes the wrong export to Story 8.3 (§ PRD lines 914, 995, 1010, 1115) — The CLI table and FR71 credit portable application export. The delivery register instead credits operational export/restore. The corrected work breakdown gives basic portable export to 8.3, operational recovery to Epic 26 and outstanding custody and erasure safeguards to Epic 34 (`epics.md:615,655`). *Fix:* Use that split in the delivery row and keep the early export outside MVP credit.

## Downstream acceptance criteria

- **[High]** Telemetry cleanup stories assign the wrong owner, time and receipt stream (§ PRD lines 557, 1063, 1213) — FR39 and NFR34 agree with the updated architecture and `EXPERIENCE.md:185–189`. Story 34.32 nevertheless assigns physical partition and mapping purge to the tenant lifecycle at handoff (`epics.md:7935–7948`). Story 34.38 sends the last-record proof to the AD-21 register (`epics.md:8216–8218`). - **[High]** The erasure stories require samples or a key that some tenants never had (§ PRD lines 557, 1063, 1170) — Stories 34.23 and 34.24 condition completion on sampled ciphertext and verified key destruction (`epics.md:7514–7521,7561–7564`). AD-16 now accepts authoritative, fenced proof that a target was empty or never provisioned, and persists the deletion identity before irreversible actions (`ARCHITECTURE-SPINE.md:222–224`). *Fix:* Add acceptance cases for a never-backed-up or partially provisioned tenant, inaccessible evidence, and worker restart after shredding. Preserve the populated-target checks and verify exactly one tombstone.
- **[Medium]** The telemetry inventory story still allows public exposure (§ PRD lines 727–740, 1105, 1213) — Story 34.40 permits the inventory to publish or mark the plane internal (`epics.md:8292–8305`). AD-12 already assigns the telemetry and clock routes to authorized internal callers and requires a new architecture decision for external exposure (`ARCHITECTURE-SPINE.md:190`). *Fix:* Require internal wire registration, error mapping, package inventory and authorized-caller tests in 34.40. Keep the wider inventory outside the narrower 34.33 register guard.
