## Delivery order and trade-offs

1. **Immediate, roughly 2–5 engineer-days.** The operating instructions are corrected in this change. Prioritize URL display and the package-floor fix. The test maintainer should reproduce the documented producer failure and map the omissions to lanes. These are bounded fixes with direct feedback. Production credential rotation, bulk reindexing and tenant deletion are outside this step.
2. **Near term, roughly 1–3 engineer-weeks for this tranche.** Implement completion on its authoritative-write and revision prerequisites. Run the expanded CI selection, the failed-live-restore drill and the ledger measurement. Budget CI minutes from observed shard timings. Persisted state and replay semantics are the main completion risks. Start reviewer recruitment and corpus curation now because they constrain the calendar independently of engineering.
3. **Larger work, several engineer-weeks per workstream.** Roll out tenant backend principals with secret rotation and revocation proof. Complete the default hybrid path and qualifying benchmark. Partition the ledger only if the measured supported profile needs it. A full architecture rewrite or a weaker launch threshold would leave the observed failures unresolved. The release owner can reconsider dates after these prerequisites have credible owners, capacity and evidence.
