# Owner configuration and recovery evidence

Explicit configured JWT algorithm lists replace initialized defaults. Absent configuration, programmatic initialization, the public init-only setter signature and existing configuration reload notifications remain compatible. Effective named bearer options and signed RSA/ECDSA acceptance with HS256 rejection execute through the registered server.

See `validation.json` for exact suite results and limitations. These candidate-source results do not establish package publication, independent signoff, remote integration or deployment. The Parties batch owns the final canonical reviewed-source and adoption identities.

Authentication algorithm policy is selected at server startup. Configuration
notifications refresh MemoriesServerAuthenticationOptions, but the registered
named JwtBearerOptions policy consumes cached IOptions and retains its startup
algorithm selection. Restart the server after changing authentication policy.
The focused registration controls exercise this behavior and programmatic options
configuration through the actual registered pipeline with no explicit algorithm
configuration. The public init-only setter ABI is unchanged.
