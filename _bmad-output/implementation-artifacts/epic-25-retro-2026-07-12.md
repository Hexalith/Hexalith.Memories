## What Went Well

1. **The composition root became legible.** `Program.cs` dropped from 4,745 to 86 lines (25.1), and that decomposition became the substrate every later story built on — 25.2's filters, 25.3's routes, and 25.4's versioning all operate on the same 7 `*Endpoints.cs` files.
2. **The designed cross-story seam actually landed.** 25.3's single-source `MemoriesRoutes` became the exact place 25.4 flipped every public path to `/api/v1/` in one edit — the cross-story dependency in the epic context, realized rather than aspirational.
3. **Behavior preservation was disciplined.** Latent bugs review surfaced (25.1's 7 endpoint edge cases, 25.4's dedup and mapper defects, 25.6's logging gap, 25.7's trust-strip leak) were correctly deferred to `deferred-work.md` instead of being absorbed into "refactor" commits.
4. **The epic learned from itself.** 25.3's Dev Notes explicitly cite the review-hardening pattern from 25.1/25.2 (keep the File List complete, prefer constant-tied assertions over substring guards), and applied it forward. Drift-guard tests became a reusable review mechanism epic-wide.
5. **Two stories refused to take the spec at face value.** 25.3 corrected two epic premises against live code (`TraverseAsync` is stable, not experimental → the reorder is a real breaking change; the "60 literals" count doesn't reconcile) and ran a throwaway .NET 10 spike to prove a "locked" compat-overload approach was infeasible (CS0121), then escalated for a maintainer decision. 25.5 and 25.6 similarly corrected false epic premises. This is the model behavior for remediation work.
6. **Full-stack proof was exercised where it mattered.** 25.4 ran the shared-topology integration lane (277 tests, 10m36s) and 25.8 ran graph integration (42/42) and release tooling — and both surfaced real signal (25.4's initial block, 25.8's benchmark red), confirming the skipped lanes elsewhere carry genuine risk.
7. **The adversarial review layers earned their keep.** All three HIGH findings of the epic (25.7 ×1, 25.8 ×2) were fail-closed or consumer-compatibility issues caught before close-out, not after.

## Challenges

1. **Submodule pointers were bumped despite an explicit "never edit submodules" rule — twice.** 25.3's published commit `8e92fe7` advanced five root submodule pointers; 25.4 (`94eb4c8`, `376096d`) advanced EventStore plus an unrelated FrontComposer pointer. 25.4's own review named it a "recurring pattern." Both were resolved identically — document and accept, no history rewrite — but nothing structurally prevents a third occurrence, and this directly contradicts the repository's submodule discipline in `CLAUDE.md`.
2. **Breaking changes landed under `feat:`/mislabeled commits — twice.** 25.3's `TraverseAsync` reorder needed three commit iterations to carry the `BREAKING CHANGE:` signal; 25.4's `/api/v1` + CLR-rename cutover landed as `feat:` and still owes a `BREAKING CHANGE:` footer on the release PR. Without it, semantic-release would cut a minor for a major change.
3. **CRLF/LF line-ending debt recurred again.** 25.3 (`git diff --check` reporting bare `\r`) and 25.8 (bare-LF normalized as LOW patches in both review passes) both hit it. This is the same unfixed lesson carried from Epics 17 and 18 — there is still no `.gitattributes` enforcement.
4. **Epic AC text drifted from the code in 3–4 stories.** The "60 server literals" count (25.3), "CLI has no `Client.Rest` reference" (25.5), and "double authorization" (25.6) were all false against the code. The stories that verified before implementing avoided shipping wrong work — but the drift itself means planning counts were never reconciled against the codebase.
5. **Drift-guard tests that passed falsely were a repeated review finding.** Reviewers caught weak guards in six-plus stories (25.1 route-source scan, 25.2 centralization guard, 25.3 route-surface regex, 25.5 DI-payload discovery, 25.6 IL decoding, 25.8 nuspec/inventory). The guards work now, but "the guard passes without proving the thing" was the epic's dominant review signature.
6. **New topology validation runs only post-merge.** 25.8 added substantial release-package and topology-drift validation, but it lives in `release.yml`, never on the PR `ci.yml` lane — so a ProjectReference re-add or a ServiceDefaults version drift can merge green. `tests/tooling/publish_nuget/publish_nuget_test.py` is edited by 25.8 yet discovered by no CI lane at all.
7. **Automation drift persisted as a process risk.** 25.3's `bmad-dev-auto` run was blocked by a branch/intent mismatch (`story/25-2…` ≠ requested `25-3…`) — exactly the mismatch Epic 24's action item #6 predicted — and 25.3 was then completed by hand. Several stories left Docker/Aspire lanes unrun under the sandbox limit.

## Team Agreements

- Remediation stories keep audit anchors narrow: verify the AC against code first, preserve behavior, and defer surfaced latent bugs to `deferred-work.md` rather than absorbing them.
- A `refactor(...)` epic can still contain breaking API changes — the breaking signal belongs on the commit and the release PR, not only in the story notes.
- Focused proof is acceptable when full-stack proof is blocked, but the blocker must be explicit, and lanes that *can* run (25.4/25.8 showed they exist for parts of the topology) should be run.
- Drift guards must prove the thing, not merely pass; prefer constant-tied assertions over substring/regex checks.
- Submodule pointers are out of scope unless a story explicitly declares them.
