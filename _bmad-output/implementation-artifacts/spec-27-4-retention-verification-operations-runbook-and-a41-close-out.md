## Trusted Evidence Contract

- **Qualification transition.** The checked-in Production overlay, the real Production namespace, and the checked-in qualification overlay remain at zero lifecycle/clock replicas. A passing C1 packet authorizes only a time-bounded, non-Production qualification session in the exact approved target/profile. C1 itself records writes disabled and `qualification_authorized: true`; it never claims that Production writes are enabled. The host-side repository runner validates target/profile/source identity, required `kubectl auth can-i` permissions, and the named approval for shared `dapr-system` effects before it acquires one namespace-scoped Kubernetes Lease, scales the qualification lifecycle/clock workloads, and opens the expiring qualification gate. It records every transition, permits only one fault at a time, and restores the gate plus lifecycle/clock replicas to disabled/zero in `finally`. C2-C4 pass only when their packets prove the final disabled state; a stale Lease or expired gate rejects and is recovered explicitly rather than bypassed.
- **Pragmatic execution boundary.** The reviewed host-side Python producers own Kubernetes orchestration, replacement/fault observation, readiness/accounting, and PostgreSQL measurement through fixed `kubectl` argument vectors. They do not call a fictional or generic `/operations/qualification/{checkpoint}/{command}` lifecycle API and do not embed a Kubernetes client in an application. Server exposes only one qualification-gated fixed-workload surface, invoked separately inside each of the two named Server pods, which emits through the normal access-telemetry logging/delivery pipeline and returns measured attempted/acknowledged/conflicted accounting. It is unavailable outside the Qualification environment, rejects an absent/expired runtime gate or wrong profile, accepts no arbitrary rate/duration/tenant/content/command input, and has focused authorization/gating/pipeline tests.
- **Repository-owned producers.** C2, C3, and C4 are fixed scenarios implemented in this repository and selected by a closed command registry. The outer CLI invokes the reviewed producer itself; an operator supplies only an allowlisted scenario-input document and target identity, never an arbitrary executable, SQL, URL, or shell fragment. The packet binds the invoked producer's repository-relative path, full source commit, Git-blob SHA-256, command ID, redacted/allowlisted argument object, and argument hash. The source path and hash must match the actual invoked file at that commit. Raw argv, environment values, secret-shaped flag names, and opaque values are never copied into evidence.
- **Fixed observations.** The runner reads workload/replacement/readiness observations with exact `kubectl` calls and performs C3 tuple/allocator measurements by executing repository-owned, fixed aggregate-only SQL with `psql` inside the PostgreSQL pod; no SQL comes from scenario input. Physical reclamation is reported through a short-lived Dapr-enabled adapter reporter Job using the deployed reviewed image, `automountServiceAccountToken: false`, no Kubernetes RBAC, and the adapter-only Dapr identity. It submits only the fixed C3 aggregate evidence to the authenticated physical-evidence route. C3 uses an exclusive, resumable journal under the external evidence root with an immutable context header and ordered entry hashes. Resume rejects any target/profile/workload/predecessor/reviewer/source mismatch, malformed prefix, replacement, or skipped observation; the journal detects mutation inside this operating boundary but does not claim cryptographic tamper evidence.
- **Bounded command capture.** Producers use streaming process capture with deterministic stdout/stderr byte limits and a bounded timeout, terminate the child on the first exceeded limit, and emit an immutable secret-safe rejection packet. Timeout and Git timeout exceptions are translated into the same bounded validation error path. A producer MUST execute, or directly control, every child command used to decide a checkpoint and create its own transcript; it MUST NOT promote operator-authored booleans, counters, timestamps, hashes, commit identifiers, SQL, or command metadata into `passed` evidence.
- **C1 predecessor.** C1 means the complete canonical 25-gate packet or 25 individually registered immutable successors. Every gate has a unique gate ID and its own attributable result plus source/artifact identity; one artifact/hash cannot discharge multiple gates. Every accepted source commit resolves locally, every artifact/source hash is recomputed from the bytes read, and every command result is inside the producer-controlled run. Packet start/finish/result times are integral UTC milliseconds, ordered, no more than one second in the future, no older than 15 minutes when accepted, and the run duration is no more than 24 hours. Boolean-as-integer and floating-point integer lookalikes fail closed.
- **C2 scenario.** The fixed workload is exactly two Server writers at the ADR cluster total of 250 accepted records/s while the component sustains at least 500 operations/s during purge, for a 30-minute steady-state window. The producer records per-writer attempted/acknowledged/persisted/conflicted counts; exact transaction acknowledgements; every Server, lifecycle-service, clock-service, Dapr-sidecar, actor-activation, Placement-member, Scheduler-member, and approved adapter replacement; and a non-empty command/result observation for each replacement. It proves zero loss of acknowledged records, reconstruction/reconnect, JSON-console continuity, and, when OTLP is configured, explicit OTLP continuity. An aggregate boolean or workload hash alone cannot pass.
- **C3 scenario.** Three distinct cohorts prove exact 1-hour, 24-hour, and 168-hour retention measured from `emittedAtUtc`. Each cohort binds an integer horizon, stable cohort ID, database/schema/table, emitted/accepted/expires/purged UTC milliseconds, pre/post tuple counts, expiry/purge/reclamation command IDs and output hashes, logical absence, preservation of named newer records, interruption/restart recovery, and physical bytes returned to the PostgreSQL allocator within 24 hours. Multi-day waiting occurs with the qualification gate disabled, and a final 125-record control proves newer data survives the 168-hour purge. The producer attributes every measurement to its command transcript; assertion booleans and one shared cohort cannot pass.
- **C4 scenario.** The closed failure inventory includes Dapr outage, application outage, state outage, clock outage, stale attestation, actor failover, reminder delay, queue-record exhaustion, queue-byte exhaustion, transaction/ETag/TTL rejection, capacity pressure, invalid configuration/key material, profile drift, reconnect, retry exhaustion, shutdown, degraded rollback, and the approved adapter fault. Each item has non-empty command/result observations and exact bounded accounting. The packet also proves JSON-console and optional-OTLP continuity, bounded signal/label sets, Unhealthy-first health precedence, NoData behavior, least-privilege inspection, raw-value absence, cross-tenant denial, privacy denial before dependency access, and absence of a tenant-facing read route.
- **Closed C0-C6 chain.** C0 validates the full adapter-profile packet, source, commands, immutable profile, and artifact hashes; C1 validates all 25 gates; C2-C4 validate the scenarios above; C5 is a named post-C2-C4 Platform Operations approval; C6 is a separately named post-C2-C4 security approval. C5 and C6 each bind the exact C0-C4 artifact hashes and profile hash, cannot share an approver, and cannot reuse the earlier C1 approvals. Terminal validation has its own closed schema, source/command/time validation, exact C0-C6 set, zero skips/failures, and recomputed hashes; three-field stubs never pass.
- **Evidence roots.** Live packets and snapshots reside under an explicit absolute `--evidence-root` outside the repository; all packet artifact paths are relative to that root and are rejected on traversal, symlinks, aliases, or escape. Reviewed source paths remain repository-relative and resolve through Git. Repository cleanliness therefore does not conflict with external immutable evidence. Packet writes are exclusive creation with closed schemas, canonical UTF-8, per-file limits, and a 4 MiB aggregate chain/snapshot limit.
- **A41 mutation integrity.** The verifier owns a non-empty exact semantic transition registry for every allowed A41 path; a manifest cannot weaken it with empty `required`/`forbidden` arrays. Preflight reads inventory and snapshot bytes once from the authenticated source HEAD Git blobs, verifies their hashes, enforces the aggregate bound before writing, records the exact index/worktree state, and protects historical Epic 20/Story 20.5 plus `sprint-status.yaml` bytes. Postflight accepts only the authentic preflight packet and exact allowed index/worktree mutation. Concurrent-edit, TOCTOU, staged-tree, and semantic drift reject without repairing files.
- **Remote publication.** Preflight binds the intended branch, exact remote name, and SHA-256 of the normalized remote URL. Publish verification revalidates those values, fetches the advertised branch into a temporary ref without mutating working files, proves the postflight commit is an ancestor of the fetched remote tip (including an advanced descendant), and rejects wrong/unfetched/remapped/unpublished commits. Repository tests use isolated local remotes; implementation performs no real push or other remote mutation.
- **Profile identity.** The approved `dc19485835a050395cf73238524d98d735dd84540cdb7cb938512e73c2a63d14` remains SHA-256 of the ADR-defined canonical identity/capability/workload object only. Rendered manifests and running node/storage/resource/TLS/image observations are separately hash-bound evidence; the appendix must not claim that those fields implicitly alter the canonical hash. A canonical-object change requires a governing decision and new approved hash.
- **Runtime observability.** Every dashboard series has a production code producer. Capacity utilization is retained-record count divided by the ADR admitted logical capacity (`250 × 3,600 × configured retention hours`) and is distinct from queue depth. A present physical-reclamation timestamp is accepted only through the adapter-evidence authority from verified C3 output; otherwise it is absent/NoData. Queue-oldest, attestation, purge-cohort, and physical-evidence ages are observable gauges derived at collection time from stored timestamps and a testable clock, so they advance while idle. Effective health is centrally aggregated with `Unhealthy > Degraded > NoData > Healthy`; runtime-gate expiry is evaluated when observed and cannot be overwritten by a later healthy subsystem update. Profile queries retain a healthy `matched` series and map only missing data to NoData. Queue record/byte/oldest gauges refresh after every mutation, including partial acknowledgement.
- **Verification.** Parse inputs fail closed for unknown fields, non-canonical UTF-8, oversized values, normalized secret aliases, invalid bounded labels, path aliases, non-finite numbers, and non-exact integer types. Every CLI mode runs through subprocess tests. Isolated-Git tests exercise the complete C0-C6/preflight/postflight/publish chain, remote-descendant success, and tampered hashes, stale/future time, dirty/staged/racing trees, wrong branch/remote URL, and unpublished commits. `MeterListener` tests collect each new instrument and prove advancing ages, profile match/expiry, health precedence, physical-evidence NoData/present, capacity utilization, and partial-ack queue refresh. Offline tests never contact a target.
- **Qualification filesystem, identity, and recovery.** C0 validates the disabled exact profile without requiring lifecycle replicas to be running. Before enable and first write, the runner binds Server/lifecycle/clock images, Dapr components/configuration, service accounts, workload identities, profile, source, and every required namespace/shared-system permission. The Server accepts the Kubernetes ConfigMap projection only when the resolved `gate.json` remains inside the dedicated read-only mount, has the exact four-field schema, and expires within the bounded session lifetime; arbitrary symlinks and far-future gates reject. Enable, renewal, and disable use stateful exact command contracts. C2/C4 renew their owned Lease and gate before expiry. Cleanup and crash recovery verify the API objects, zero replicas, released/expired Lease, and the disabled gate observed inside every Server pod before reporting success.
- **Evidence chronology.** The 15-minute C1 freshness gate is evaluated once at authorization for each bounded qualification session and recorded in that session transition. It is not reapplied after C2's 30-minute run, between C3's 1h/24h/168h observations, or at terminal close-out. Retained C0-C6 evidence instead validates immutable hashes, source/profile identity, ordered capture times, per-command bounds, and approval chronology; current-wall-clock freshness applies only to a newly opened authorization or approval, never retroactively to an immutable predecessor.
- **Correlated workload and exact accounting.** Every fixed record carries a bounded internal run/segment identity used only for qualification accounting. The Server returns observed attempted/enqueued/persisted/conflicted/rejected/dropped deltas for that run, never process-global traffic or a substituted expected count. Queue expiry records drops; partial/multi-record acknowledgements remove and count the exact records. C2 waits for both writer-start barriers, measures actual overlap and elapsed steady-state rate, uses idempotent segment identities plus read reconciliation after lost responses, measures component/purge operations from target counters, and proves per-acknowledgement survival so concurrent inserts cannot mask loss.
- **C3 logical and physical proof.** Every cohort binds emitted <= accepted <= expires <= purged times, configuration/actor epochs, target/profile/workload/source hashes, stable identities for all 125 newer control records, Dapr expiry-catalog deletion, strong absent reads, and PostgreSQL tuple/allocator observations. The reporter receipt binds the complete immutable cohort/transcript packet and the C1-approved deployed image digest, not one aggregate. Resume paths execute in tests and cannot depend on an unimported helper or recreate an already-completed reporter Job ambiguously.
- **C4 isolation and continuity.** Each fault starts from and returns to a verified clean baseline; terminalized Server delivery workers are restarted before the next lane. Scenario-specific expectations distinguish zero-loss recovery from intentional rejection/drop. Business continuity uses a fixed authenticated business operation, not readiness. JSON-console, optional OTLP, health, and alert evidence is correlated to the run and fault interval and observed at the actual sink/rule state. Tenant/privacy denial is exercised against the deployed target before dependency access; local tests or synthesized counters are supporting evidence only.
- **Executable contract tests.** Tests render `deploy/kubernetes/overlays/qualification`, validate all named resources/zero defaults/gate mount/reporter security/RBAC, and drive a stateful Kubernetes double that applies the exact Lease/gate/scale commands and readbacks. - **Authenticated execution and bounded duration.** The verifier executes private immutable copies of the authenticated producer, support module, manifest/SQL registry, and scenario input bytes; no checked path is reopened by name after hashing. Each checkpoint timeout is derived from the sum of its declared command/wait/cleanup bounds plus margin. - **C2 execution topology and proof.** The host drives individually bounded one-second segments and reselects ready pods after each replacement; no 30-minute proof is owned by an exec session inside a pod that the same scenario must terminate. Segment responses bind the exact run, actual writer pod, canonical segment ID, stable 125-record identity set, and exact dispositions. ## Design Notes

The repository change produced by this run prepares and verifies evidence machinery; it is not the A41-closing commit. The qualification lane uses the exact approved deployment profile in a non-Production namespace and always restores lifecycle writes disabled; it never weakens the checked-in Production zero-replica overlay.
