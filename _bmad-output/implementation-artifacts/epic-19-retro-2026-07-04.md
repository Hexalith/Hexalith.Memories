## What Went Well

1. **Completed epic history stayed intact.**
   Epic 19 referenced Epic 15 and Epic 18 as sources of residuals but did not rewrite their completion history. That preserved traceability and avoided mixing "done" delivery evidence with later planning decisions.

2. **The anti-over-promotion guardrail held.**
   Stories 19.2, 19.3, and 19.4 selected zero implement-now work. Each accepted decision was tied to a trigger, a rationale, and a natural future home. This was the right outcome for a governance epic whose core risk was accidentally turning low-value residuals into mandatory implementation.

3. **The deferred register became a usable planning artifact.**
   The new Story 19.1 through 19.4 rollup sections make it possible to tell which entries are accepted, which entries route to future work, and which residuals require re-evaluation when their trigger fires.

4. **Parser-backed governance worked.**
   `deferred-work.md` has a structured schema, and every story treated `CiTestInventoryTests` as the load-bearing proof. That kept Markdown governance from becoming unvalidated prose.

5. **The CI metadata cleanup caught a real release blocker.**
   The 19.5 artifact shows the stale root-level gitlink would break CI and release submodule initialization. Fixing metadata while preserving the root-declared `references/` rule directly supports the repository's submodule policy.

## Challenges

1. **Accepted-until-trigger entries still need active review.**
   Epic 19 reduced ambiguity, but it did not remove the underlying risks. If future story creation does not re-check accepted entries against current triggers, the register can become passive documentation instead of planning signal.

2. **One-shot work can drift from sprint tracking.**
   `19-5-ci-submodule-metadata-cleanup.md` is useful and complete, but it is not represented in the Epic 19 development status rows. That is acceptable if treated as a one-shot artifact, but the convention should be explicit so retrospectives and status tracking do not diverge.

3. **Line-ending debt remained noisy.**
   The story records repeatedly mention CRLF/LF handling and `git diff --check` caveats. This is the same line-ending action carried from Epic 17 and Epic 18. It did not block Epic 19, but it still consumes attention.

4. **Architecture drift was not fixed here.**
   Epic 18 identified stale architecture anchors. Epic 19 classified residuals but did not reconcile `architecture.md`. The 2026-07-04 audit now makes architecture reconciliation a harder requirement across Epics 20, 21, 24, and 25.

5. **Validation was intentionally narrow.**
   The governance stories validated the deferred-register parser. They did not run broad runtime, Docker, Aspire, migration, or production-readiness lanes. That is appropriate for the story scope, but it means Epic 19 did not reduce the runtime risks now captured in Epics 20-26.
