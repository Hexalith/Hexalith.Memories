## Discussion — What Went Well

> Alice (Product Owner): "I'll start with the obvious one. We delivered the entire CI/CD foundation in a single working day — both stories from `ready-for-dev` to `done` on 2026-04-26."

**Concrete wins worth replicating:**

1. **Single-source-of-truth pattern for test inventories.** `tools/test-projects.unit-contract.txt`, `…integration-fast.txt`, `…benchmark.txt` are read by every script and the workflow, with `CiTestInventoryTests` asserting drift detection. This pattern caught P4 (test-release.ps1 reintroducing a divergent list) and is reusable wherever "same list in N places" appears.
2. **Reflection-based contract coverage** (`PublicContractSerializationCoverageTests`). Discoverability beats manual lists — if a new public `Contracts.V1` type ships without a round-trip test, CI fails. Generalizable to any "must enumerate every X" requirement.
3. **`pack-release.ps1` build-once-pack-many redesign** (D7). One solution-wide `dotnet build -p:Version=$Version`, then loop `dotnet pack --no-build` per package. Eliminates a class of diamond-dependency intermediate-metadata bugs that wouldn't have shown up until the first multi-package release.
4. **Bundled adversarial review on a coupled diff.** Reviewing 11.1 + 11.2 together (because they shared workflow files, scripts, and CONTRIBUTING.md) found cross-story drift (P3 action versions, P4 inventory) that two separate single-story reviews would likely have missed.
5. **Task 0 "reconcile inventory before writing YAML"** in 11.1. Catching that `tools/test.*` was missing `Mcp.Tests` and `EventStore.Tests` — and including `Benchmarks` it shouldn't run — *before* writing CI YAML prevented a green-but-misleading first run. Load-bearing scoping work.
6. **Integration-fast stabilization made a real signal.** The first run failed 11 tests (MCP DAPR, audit/log streams, semantic ranking). Fixing them produced 159/49/0 — the signal is now trustworthy rather than "always-flaky-so-ignore."
7. **Course correction is now a visible status, not a buried concession.** W10's "External Action Pending" header on `11-1-…md` makes AC #6's maintainer dependency unmissable. This is a documentation pattern worth keeping.

## Discussion — What Didn't Go Well

> Amelia (Developer): "Now the harder half. None of this is blame — these are systemic patterns to learn from."

> Charlie (Senior Dev): "I want to flag the biggest one first: D5."

### Pattern 1 — Story file-scope guardrail is unenforced

**What happened:** Story 11.2's spec explicitly said *"Avoid runtime `.cs` changes unless Task 0 deliberately changes package boundaries. This story should not change service behavior."* The bundled diff included **runtime `.cs` changes** in `src/Hexalith.Memories.AppHost/Program.cs`, `src/Hexalith.Memories.Mcp/McpCompositionRoot.cs`, and `src/Hexalith.Memories.Server/Search/SemanticSearchService.cs` — all unanchored to specific tasks until D5 forced explicit anchoring in completion notes.

**Why it happened:** Integration-fast had to actually pass for AC #4. Pre-existing reliability issues (MCP DAPR app-id drift, semantic-ranking non-determinism, cancellation conflation in stream readers) only surfaced *because we finally had a CI lane that ran them*. Fixing them was the right call — but it leaked into a story whose file-scope guardrail forbade it.

**Why this matters:** No tooling enforced "this story should not touch `src/**/*.cs`." Future infrastructure stories will repeat this pattern unless we do something concrete.

### Pattern 2 — Pre-existing baseline failures hid behind "review → done" transitions

**What happened:** When 11.1 first ran the Docker-free lane, three Server.Tests were failing — not new failures, but pre-existing ones inherited from the Story 8.5 Rev 0.2 era:

- `Validate_Event_WithNullBytes_Throws` (Server.Tests)
- `RunAsync_IndexAlreadyExistsWithMatchingSchema_ShouldReturnTrue` (Server.Tests)
- `EventStoreIntegrationDoc_HasRequiredSectionsAndKeyContent` (Server.Tests)
- Plus `EmbeddingInputContentKindTests.ContentKind_PropagatesToEmbeddingApiCallsMetricTag`

11.1 fixed three of them; the fourth is now tracked as **S11-FA** baseline filter in `test-release.ps1`.

**Why it matters:** Stories 8.5, 9.1, 9.2, 9.3, 10.1, 10.2 all transitioned to `done` while these tests were red. Without CI, "all tests pass" was tribal knowledge maintained by `tools/test.*` filters. **The absence of CI created an authoritative-greenness vacuum** that let baseline failures accumulate. Epic 11's first job was effectively repaying that debt.

### Pattern 3 — Silent-failure idioms appeared in multiple places

The review surfaced four distinct silent-failure patterns in a single epic:

| Pattern | Location | Caught by |
|---|---|---|
| Process-substitution swallows exit code | `tools/test.sh` `read_inventory` | P2 |
| `if-no-files-found: ignore` masks pack failure | `release.yml` upload step | P15 |
| `--skip-duplicate` masks partial NuGet publish | `tools/publish-nuget.ps1` | D4 (accepted, S11-FD alerting deferred) |
| Per-project zero-test count silently passes verifier | `tools/verify-integration-fast-coverage.py` | D8 |

All four are the same shape: a layer designed to be "tolerant" hides a real failure. Worth treating as a **category** rather than four unrelated bugs.

### Pattern 4 — Convention drift between sibling files

Without a structural check, sibling files diverge:

- `release.yml` pinned actions at `@v4` while `ci.yml` shipped at `@v6`/`@v5` (P3)
- `tools/test-release.ps1` reintroduced a hand-maintained project list that already lived in `tools/test-projects.unit-contract.txt` (P4) — within the same epic that *centralized* the list
- `validate-release-packages.ps1` used PowerShell's case-insensitive `-ne` for PackageId comparison (P11) — would have permitted a lowercase-vs-canonical drift to lock the wrong case on nuget.org

The drift-detection guard (`CiTestInventoryTests`) caught one instance after the fact. There is no equivalent guard for action versions or for case-sensitivity of identifier comparisons.

### Pattern 5 — Status checkboxes can lie about reality

W10: AC #6's `[x]` task checkboxes were correct from a documentation perspective (the docs were written), but misleading from an outcome perspective (branch protection was not yet applied). The course correction added an explicit `External Action Pending` header — a pattern we now have, but it was a post-`done` patch, not a pre-`done` discipline.

### Pattern 6 — Untracked file caught only at review (P1)

`package-lock.json` was in the working tree but untracked. The release workflow's `npm ci` would have failed on first run. Caught by the human review pass, not by any pre-commit / pre-push check.

## Key Insights

1. **CI is the missing keystone for trust in tribal "done" states.** Six prior stories shipped with red baseline tests because the green-or-not signal lived in developer machines, not in repository state. Epic 11 doesn't just *add* CI — it *retrofits* a truth signal that should have been load-bearing earlier. Expect more S11-FA-style baseline-cleanup follow-ups as the new lane runs against history.

2. **Bundled stories with shared infrastructure deserve bundled review.** The 3-layer adversarial pass on the unified 11.1+11.2 diff found cross-story drift that single-story reviews would have missed. This bundling pattern is worth a permanent slot in the team's review playbook for coupled work.

3. **Tolerance idioms are a category to govern, not isolated bugs.** "Don't fail when no files match," "don't fail when no tests run," "skip duplicates silently" — these read as defensible defaults but compound into a green-but-broken pipeline. A simple "list of forbidden default tolerances" in a CONTRIBUTING / code-review checklist would have caught all four patterns at once.

4. **The roadmap is exhausted.** Epic 11 is the last planned epic. Everything after this is **post-MVP**: a real first release, branch protection turn-on, contributor onboarding observation, runtime hardening, possibly Phase 2 work that the deferred items keep referencing (per-tenant LLM config, tokenizer-accurate budgets, projection registries, etc.). The team needs an explicit decision about *what comes next*, not an automatic "create Epic 12" reflex.

5. **External-action items deserve first-class tracking.** AC #6 (branch protection) and the future `NUGET_API_KEY` secret turn-on are both maintainer-only and both invisible from inside the repo. The W10 `External Action Pending` header pattern works — extend it to the NuGet-publishing path.
