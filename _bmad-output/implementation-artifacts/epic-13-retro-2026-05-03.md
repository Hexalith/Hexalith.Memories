## What Went Well

1. The epic respected the phased dependency chain.

   Story 13.6 waited for 13.2, 13.3, 13.4, and 13.5. Story 13.7 waited for 13.6. That prevented integration and migration work from inventing contracts before the lower layers existed.

2. Google behavior stayed protected while Ollama was added.

   Story 13.1 preserved Google defaults and validation. Story 13.3 preserved Google dispatch. Story 13.7 kept the default Google/fake ingestion regression green while adding the Ollama OIDC path.

3. Secret discipline improved across multiple layers.

   OIDC secrets remain in DAPR secret storage. Bearer tokens and client secrets are not persisted or exposed through tenant APIs. Reviews repeatedly converted weak substring checks into assertions against actual secret/token values.

4. The review process caught real behavioral risks.

   Examples include OIDC cache races, redaction-before-truncation, refreshed-token redaction, BaseUrl validation branches, actor serialization shape, migration confirmation gates, live-migration ordering, YAML injection in test secret names, fake-server races, and timeout payload scrubbing.

5. The migration story became operationally explicit.

   Story 13.6 turned a risky provider/dimension change into an operator surface with dry-run inventory, explicit live mode, per-tenant handling, progress/failure summaries, and resume metadata.

6. Documentation landed with the final proof story.

   `docs/operations/embedding-providers.md` and `docs/dev/embedding-providers.md` describe the provider matrix, gateway contract, OIDC/Keycloak setup, secret-store layout, migration path, and test surfaces.

## Challenges

1. "Provider pluggability" hid cross-cutting complexity.

   The provider switch touched defaults, validation, HTTP request shape, token acquisition, actor state, endpoint serialization, Redis Vector dimensions, migration safety, integration fixtures, and operator docs. Future provider work should assume this full surface from the start.

2. Security findings repeated across stories.

   Secret and bearer redaction appeared in 13.2, 13.3, 13.5, 13.6, and 13.7. The system handled the findings, but the repetition suggests a shared redaction policy and test helper would reduce risk.

3. Migration safety required design correction during review.

   Story 13.6 changed confirmation gates, mutation ordering, rollback wording, index recreation cleanup, field preservation, progress accounting, and failure taxonomy during review. This was valuable, but it shows migration stories need sharper pre-dev acceptance boundaries.

4. Deferred hardening grew materially.

   The accepted deferred set includes OIDC cancellation and HttpClient lifecycle, transport exception wrapping, circuit-breaker behavior, provider/model registry hardening, migration-vs-ingestion race handling, redactor shape expansion, test fixture cleanup, and sprint-status line length.

5. Submodule discipline was stressed.

   Story 13.5 accepted an innocuous `Hexalith.EventStore` pointer drift in place, but documented that future feature commits should not bundle submodule pointer movement without explicit scope.

6. Local aggregate validation remained noisy.

   Focused and relevant lanes were strong. Some broad aggregate runs did not complete locally, so story records correctly separated proven lanes from unproven aggregate attempts.

## Significant Discoveries

1. Embedding providers are operational domains, not simple adapters.

   Adding Ollama required tenant state migration, Redis Vector schema changes, OIDC token management, gateway contracts, DAPR secrets, fake infrastructure, and operator runbooks. Future provider additions need an explicit story chain or sprint change proposal.

2. Provider/model/dimension validation should move toward a registry.

   Story 13.1 exposed cross-pollination risk. Story 13.4 tightened the regex and non-Ollama OIDC behavior, but a full provider-to-model-to-dimensions allowlist remains deferred for the next provider/model expansion.

3. Path A migration is acceptable for current data assumptions, but live coordination remains a known risk.

   Story 13.6 intentionally did not solve concurrent ingestion racing migration. That is the most important operational caveat before any live tenant migration with meaningful traffic.

4. OIDC runtime hardening has clear re-open triggers.

   Leader cancellation, handler rotation, concurrent forced refresh, stale secret rotation, and persistent 401 behavior are not story blockers, but they are the correct hardening list for production stress.

5. The current roadmap has no Epic 14 definition in `epics.md`.

   No concrete next-epic plan update is required. The Epic 13 lessons should be treated as entry criteria for the next provider, migration, or operations epic.

## Team Agreements

- Provider additions require a full cross-layer checklist: defaults, config, validation, client dispatch, secrets, migration, integration fixtures, operator docs, and deferred-work triage.
- Do not treat vector dimensions as a benign setting; provider/model/dimension changes are migration events.
- Redaction tests must assert against actual sensitive values, not incidental substrings.
- Story prerequisites must be enforced in both sprint status and story artifacts before dependent implementation starts.
- Migration tools must be explicit about dry-run, live mode, resume behavior, failure recording, and operator verification.
- Defer consciously with re-open triggers; do not hide hardening debt inside vague "future work" notes.
