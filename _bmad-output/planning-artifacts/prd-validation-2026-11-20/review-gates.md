# Release-gate review · 20 November 2026

**Verdict.** The November no-go is consistent with the decision record. The following six acceptance rules need clarification before different reviewers can reproduce the same verdict. The missing G1 reviewers, unfinished target CLI, pending walkthroughs and eight-topic diagnostic run are already recorded accurately. The four G6 conditions cover current evidence, ownership, the tracker and the limited tracker-freeze exception. [Current PRD](../prd.md#measurable-outcomes) · [November decision](../sprint-change-proposal-2026-11-20.md) · [Evidence addendum](../addendum.md)

- **[critical]** L1 cannot score its held-out topics (§ PRD line 204) — The row requires “≥10 topics not used in G1 labelling” and identifies “the frozen G1 labels” as the scorer. Those labels cannot establish relevance for a held-out topic. With 12 topics the literal “≥ 8/10” also allows either eight successful citations or ten. The September review raised both defects. The later decision log adds the citation threshold, and current Epic L1 repeats the same label source. *Fix:* Freeze and independently grade a disjoint L1 topic-to-unit relevance file before the run. Specify the relevance cutoff and use either exactly ten topics or at least 80% across the entire set. [September finding](../validation-report.md) · [Decision log](../.memlog.md) · [Current epic gate](../epics.md)
- **[high]** G1 does not specify how reviewer grades become NDCG gains (§ PRD lines 171–177, 191) — “Graded labels” and pairwise Cohen’s κ establish agreement but leave the final grade and gain function unspecified. With individual grades of 0, 0 and 3, a median yields 0 and a mean yields 1 even when overall pairwise agreement passes. The existing scorer explicitly uses “binary relevance” and accepts a list of relevant IDs, so it cannot settle the graded protocol. *Fix:* Before independent labelling, register the grade scale, disagreement or abstention procedure, final judgment per topic/unit, gain mapping and treatment of unjudged items. Freeze those judgments and the scorer version with the corpus. [Diagnostic scorer](../../../tests/Hexalith.Memories.Benchmarks/Scoring/NdcgScorer.cs) · [Corpus freeze story](../epics.md#story-336-freeze-the-real-phase-1-corpus-and-topics)
- **[high]** L3 counts both events and chains (§ PRD lines 185, 206, 679) — The criterion says “95%+ of EventStore events” and specifies “at least 20 chains,” then measures “95%+ of the named known-chain fixture fully traversable.” With nineteen complete two-event chains and one wholly unavailable twenty-event chain, chain weighting yields 19/20 = 95% while event weighting yields 38/58 ≈ 66%. The current PRD has repaired the historical fixture-location issue and identifies the extension it needs. *Fix:* Select one scoring unit and denominator, specify the expected complete path for each unit, and require the fixture report to emit the numerator and denominator. [Event-ingestion fixture](../../../tests/Hexalith.Memories.IntegrationTests/EventStoreIntegration/EventIngestionPipelineIntegrationTests.cs) · [Graph gap fixture](../../../tests/Hexalith.Memories.IntegrationTests/Graph/GapDetectionIntegrationTests.cs)
- **[high]** G2 can accept a successful tenant-mismatch response that FR44 requires to fail (§ PRD lines 192, 402, 1068, 1152) — NFR8 allows a request explicitly naming tenant B to be “rejected or [return] only A’s data.” FR44 requires “rejecting cross-tenant requests with clear errors,” and Journey 5 promises a tenant-mismatch error. A server silently retargeting B to A can pass the G2 test while violating the product contract. *Fix:* Require rejection and zero side effects for an explicit conflict in both directions. Test ordinary claim-derived scoping separately for routes that permit tenant omission. [Principal-isolation requirement](../prd.md#security)
- **[medium]** G5 has conflicting Phase 1 surface requirements (§ PRD lines 195–198, 1129, 1188–1190) — Phase 1 “does not require MCP,” but the G5-referenced NFR25 mandates golden-vector tests “across REST, CLI JSON, and MCP” and carries an MVP tag. One reviewer can qualify REST/CLI alone while another withholds G5 pending MCP evidence. An inactive preview can support a component test, but the PRD does not say which evidence earns the Phase 1 verdict. *Fix:* Enumerate the Phase 1 G5 participants, distinguish any required offline contract fixtures, and bind end-to-end MCP parity to its activation gate. [Phase decision log](../.memlog.md)
- **[medium]** L2 starts in an application absent from its clean-machine baseline (§ PRD lines 205, 208–213, 947, 1205) — The clock starts at package installation “in an existing EventStore-based service.” The clean profile contains “only Docker and the SDK,” and step 4 boots the sample AppHost. A runner can receive a prepared checkout and ready service before timing, while another must acquire and prepare them. Both can report the same five steps with materially different elapsed times. *Fix:* Version the starting service and sample together, define which checkout, dependency caches and tools can be present at time zero, and require the step-5 event to originate in the step-1 service. Keep the approved provider-key, Aspire-installation and image-pull rules.
