## Intent

**Problem:** The Server runtime qualification gate still accepts historical PG-ONPREM-1 while the approved current profile and Python producers require PG-ONPREM-2. Existing tests build gate input from the runtime's own constant, so they cannot detect an incorrect profile pin.

**Approach:** Pin the runtime gate to the published exact PG2 hash and test it with independent published PG2/PG1 values. Prove current-profile acceptance, historical/wrong-profile rejection, Qualification-only access, bounded expiry and fresh-file renewal. Update the current canonical prerequisite handoff with repository evidence, retaining historical receipts and all pending live qualification, approval, Production and A41 boundaries.
