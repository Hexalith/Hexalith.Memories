Critical

VAL-C01 · MemoryUnit commit, projection completion, and rebuild do not form one integrity contract

The document requires EventStore acceptance and rebuildable projections, but ordinary file/URL ingest schedules the workflow directly with no authoritative MemoryUnit create event or source version. Verification records presence booleans; a missing projection becomes a warning before an unconditional Indexed return. Repair enumerates derived stores, treats syntactic Redis as authority, and cannot recover an all-three-absent unit.

Evidence: architecture.md:45, 98, 292, 582, 1598–1620; IngestionEndpoints.cs:108–142, 303–320; IngestionWorkflow.cs:433–465, 608–623; index-rebuild runbook.

Discuss, then update code and spine together. Bind the authoritative event, identity, retained payload/reference, source version, durable scheduling handoff, projection receipts, sole indexed transition, replay enumerator, and end-to-end failure tests.

Critical

VAL-C02 · Tenant-principal isolation conflicts with process-wide backend credentials

The selected per-tenant Redis ACL and routing boundary conflicts with singleton, process-wide Redis/FalkorDB connections used by current search and indexing. Tenant deletion also leaves dedup reservations that can affect a recreated tenant. Existing collision tests verify key shaping, not the claimed principal boundary.

Evidence: architecture.md:71, 76, 280–284, 603–648; ServiceDefaults/Extensions.cs:76–100; DeleteTenantDataKeysActivity.cs:50–79.

Discuss. Choose one enforceable credential/connection owner and bind provisioning, cache, rotation, revocation, deletion/recreation, workflow fencing, and negative evidence across both Redis and FalkorDB.
