## Design Notes

Both original Ask-First items are resolved and implemented (see Spec Change Log): package identity ships via a rebuild-under-mandated-SDK published to a durable, tracked-and-scoped isolated local NuGet feed (`tools/nuget-local-feeds/hexalith-eventstore-999.1.20-proof.fa2d1c9910f8/`, wired into `NuGet.config` via `packageSourceMapping`), and the `eventstore` resource's Dapr sidecar mirrors the `memories` resource's `WithReference(stateStore/pubSub)` pattern. Remaining work is Task 4 only: EventStore's own command/aggregate surface (distinct from Memories' Tenant/Case aggregates already routed through `EventStoreMemoriesCommandStore`) needs to be invoked directly against the live `eventstore` resource so EventStore's own runtime performs the Dapr publish, with a CloudEvent `source` that Memories' tenant-routing maps to a tenant -- see the Task 4 checklist entry for the specific gap found.

A note on the local feed's signing: this repo's `NuGet.config` enforces `signatureValidationMode=require` globally (Story 8.5 ADR-8.5-001(b), a real supply-chain control against nuget.org typosquatting/cache-poisoning). That setting is not scopable per package source, so an unsigned local feed fails restore with `NU3004`/`NU3027` even when correctly source-mapped. Rather than weaken that policy repo-wide (which would reduce security for every package, not just this one), the local feed's 14 packages are author-signed with a throwaway, non-committed self-signed certificate, RFC-3161-timestamped, and trusted by SHA-256 fingerprint only (`allowUntrustedRoot="true"`).

A second note, added after human review: the `trustedSigners/author` trust entry for that certificate was initially added directly to the tracked `NuGet.config`, then relocated to a gitignored, local-only `tools/nuget-local-feeds/NuGet.local.config` override. Reason: NuGet's trust model is not scoped per package source -- `packageSourceMapping` only controls which source is *queried* for `Hexalith.EventStore.*`, but a `trustedSigners/author` entry trusts that certificate fingerprint for *any* package from *any* configured source, repo-wide. Landing that in the tracked, shared `NuGet.config` would have been a real (if narrow) security-policy weakening reaching `main` without explicit review, especially given the auto-push risk already observed this session (see prior Spec Change Log entries). The existing nuget.org `trustedSigners/repository` entries in the tracked `NuGet.config` remain untouched throughout.
