# Validation Remediation Contract

This working artifact deduplicates the 2026-09-09 validation report and its four reviewer files into the acceptance checklist for migrating the legacy UX package to `DESIGN.md` and `EXPERIENCE.md`. It does not assert that any item is fixed. The consolidated contract contains **3 critical, 17 high, 9 medium, and 3 low** findings.

## Authority and precedence

1. The current change-controlled [PRD](../../../prd.md) and repository [Hexalith UX instructions](../../../../../references/Hexalith.AI.Tools/hexalith-ux-instructions.md) are binding.
2. The validation package is remediation evidence. It overrides the May legacy UX where it reconciles drift, but it cannot override a newer PRD decision, a versioned product contract, architecture ownership, the centrally selected Fluent package, or repository instructions.
3. The legacy [UX specification](../../../ux-design-specification.md) and [HTML direction study](../../../ux-design-directions.html) are migration inputs only. The new spines win on conflict.
4. Items marked **DEFER** require an owning source or an explicit decision. The migration must expose the unresolved boundary rather than inventing a value, wire name, phase activation, or product capability.

## Migration blockers and explicit deferrals

- **Product decision required before final web behavior:** default compact trust fields versus opt-in `--explain` detail. Preserve it as an open item until explicitly resolved under the PRD’s change-control path.
- **Contract/architecture ownership:** MCP field names, `Contracts.V1` response/error shapes, status-enum renaming, RRF numeric weights/defaults, freshness thresholds, and authorization mechanisms are references, not UX inventions.
- **Product/sprint ownership:** journey phase, capability delivery state, web activation, audit/ACL scope, and future surface authorization remain governed by the PRD and approved sprint change.
- **Repository ownership:** the central package catalogue and Hexalith UX instructions override copied package pins, mock component names, and alternate page-section patterns.
