### Process lessons

- **L1:** Acceptance evidence must exercise the surface the story changed. A sibling path proving the same component shape (29.1's root AppHost proving 29.2's extensions) is supporting evidence, not closure (F1, F6).
- **L2:** When a story generalizes a surface a sibling story just hardened, port the sibling's boundary checks (key allow-lists, store names, init gates) and test them on the new path (F2, F3).
- **L3:** Public-API changes to a packable library need an automated breaking-change signal. Reviewer acceptance of a missing footer cost a downstream consumer three call-site flips in five days (F4).
- **L4:** Run the story's own new tests on a fresh CRLF checkout before setting `done` (F16).
- **L5:** Live-topology evidence measured once on a developer workstation (NFR7 3.2 s) is not lane evidence. CI measured 132–192 s and needed five stabilization fixes (F13).
- **L6:** Commit type and scope drive the release. A story-file-only commit typed `feat:` cut v2.13.0, while the feature itself shipped as `fix:` (F15).
