## What Went Well

1. **Decision-first sequencing worked.**
   Story 21.1 forced the consistency model decision before A3 implementation. That prevented the epic from hardening direct Redis/FalkorDB writes as if they were the final architecture.

2. **Review fixes caught operationally significant defects.**
   Reviews found unobserved child workflows, missing Dapr workflow activity registration, migration inventory miscounting, missing tenant index repair, owner-check race gaps, duplicate detector false positives, rollback marker overwrite, and staging index cleanup gaps.

3. **Key-schema centralization reduced future migration risk.**
   Story 21.4 moved production key and index construction behind helpers and added a guard against raw production memory/vector literals. That directly supports Epic 22 retrieval work.

4. **Migration safety moved from destructive to recoverable.**
   Story 21.9 introduced staging keys/indexes, alias cutover, rollback, owner locks, heartbeat, abort, and deleted-tenant cleanup. Story 21.10 then added coverage for wrong dimensions and rollback end states.

5. **Previous Epic 20 practices carried forward.**
   Stories kept audit-anchor preflight, preserved auth/tenant/security regression guards, and used docs as part of close-out evidence.

## Challenges

1. **Implementation touched many shared paths.**
   Consistency, case mutations, tenant lifecycle, ingestion, EventStore intake, vector migration, search key construction, tenant deletion, and operator docs all moved in one epic. The blast radius was high.

2. **Several defects only appeared during review.**
   The recurring pattern was not lack of effort; it was missing adversarial coverage for workflow dispatch, rollback semantics, and race cleanup. Review became a necessary quality gate, not ceremony.

3. **Environment limitations constrained integration proof.**
   VSTest was blocked by sandbox TCP listener permissions. Docker/Testcontainers RedisStack lanes compiled but could not execute where Docker socket access was denied. Story records generally handled this well by using xUnit v3 in-process fallbacks and documenting blocked lanes.

4. **Documentation still drifted around cross-epic contracts.**
   The post-retro verification found stale phrasing in architecture and consistency docs after the code had moved to EventStore command boundaries and opaque memory-unit IDs.

5. **File List and evidence hygiene required repeated correction.**
   Multiple reviews fixed story File List drift. The process improved, but the pattern is still visible enough to keep as an action item.
