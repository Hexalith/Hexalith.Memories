## What Went Well

- Story 9.1 established the zero-code ingestion path through a publishable `Hexalith.Memories.EventStore` package, canonical DAPR subscription discovery, CloudEvents parsing, tenant/case routing, preflight deduplication, and Server-owned adapters.
- The package boundary was kept clean. EventStore integration owns the public adapter contracts while the Server supplies workflow scheduling, tenant status, case creation, telemetry, and Redis-backed dedup implementations.
- CloudEvents metadata became first-class memory metadata. `id`, `source`, `type`, `subject`, `time`, and derived aggregate type now survive ingestion and are available for filtering and diagnostics.
- Story 9.1 closed real end-to-end mismatches discovered during validation: event workflow IDs no longer leak into persisted memory IDs, inline event payloads are accepted correctly, and DAPR subscription discovery follows the canonical `MapSubscribeHandler()` route.
- Story 9.2 delivered the hard part of the EventStore promise: raw-payload embeddings, natural-language event descriptions, NL vector indexing, degraded retry behavior, causal edge correction, and explicit stub/gap-marker semantics.
- The team treated DAPR Workflow replay safety as a serious compatibility issue. Startup gating, SDK-surface probes, and follow-up guard tests were added instead of assuming replay behavior would remain stable.
- Story 9.2 improved consistency semantics by separating action-required discrepancies from informational notes. That makes the consistency surface more accurate as natural-language indexing introduces eventual-completion states.
- Story 9.3 completed FR62 with handler snapshots, mismatch categories, REST client methods, CLI commands, metrics, and observation-store plumbing.
- Handler mismatch detection was scoped pragmatically. The story surfaced `UnhandledEventType`, `StaleHandler`, and `VersionMismatch` without adding hot-path behavior or pretending to solve projection-registry ownership.
- Review close-outs were substantive. Several rounds found real issues in Redis observation cap enforcement, startup logging, formatter wiring, workflow-name reflection, note/discrepancy counts, and atomic observation writes.

## Challenges

- Epic 9 touched many load-bearing surfaces at once: DAPR pub/sub, DAPR Workflow, DAPR Conversation, Redis Vector, RediSearch, FalkorDB, source-generated JSON contracts, Server composition, REST client, CLI, docs, telemetry, and consistency verification.
- Zero-code integration is not only an ingestion feature. It forces decisions about idempotency, tenant routing, case creation, event naming conventions, subscription discovery, replay, dead-letter behavior, and operator diagnostics.
- DAPR and SDK surface gaps shaped the implementation. The team had to work around missing Conversation logprobs, limited Workflow metadata, alpha Conversation API warnings, and testability limits around workflow state.
- Natural-language embedding adds an eventually-complete axis. The system remains functional when LLM work is unavailable, but retry backpressure, dead-letter operator surfaces, and deeper integration proof remain follow-up work.
- Handler observation fidelity is intentionally incomplete. The current observation model records tenant, aggregate type, and event type, but not source-prefix fidelity or true rolling-window counts.
- Memories Server authN/authZ was discovered as a cross-cutting gap during Story 9.3. The story correctly descoped endpoint-specific auth because the server lacks a coherent auth posture today.
- Tier-2 and Tier-3 coverage is uneven. Unit and focused regressions are strong, but several topology-sensitive tests for dual embedding, handler endpoints, observation write behavior, and replay safety remain deferred.
- Review effort surfaced a pattern: later review rounds were useful, but some findings corrected over-build from earlier rounds. Future complex stories should deliberately stop when new findings become mostly corrective churn.

## Key Insights

1. The zero-code promise is an operations contract, not just a developer-experience claim.
2. Event ingestion must stay idempotent at every boundary because DAPR delivery is at-least-once and ordering is not guaranteed.
3. Dual embedding needs a degraded path by design. LLM unavailability must reduce semantic richness, not drop events.
4. Causal graph semantics need conservative modeling. Correlation roots, self-edge guards, and gap markers are compatibility-sensitive behavior.
5. Diagnostic surfaces become public APIs as soon as operators depend on them. Handler CLI output, mismatch categories, metrics, and observation fields need versioning discipline.
6. Deferrals are acceptable when they are explicit, named, and tied to re-open triggers; Epic 9 has many of these, and they need active triage before release hardening.

## Significant Discovery Check

No Epic 9 discovery invalidates the direction of Epic 10, which is already complete.

Significant discoveries that affect release hardening:

- Memories Server has no coherent authN/authZ posture. Endpoint-specific auth would be inconsistent until the Server boundary is addressed as a whole.
- Handler observation fidelity is good enough for diagnostics, but not yet precise enough for per-source-prefix operational guarantees.
- Natural-language event embedding is intentionally degraded-tolerant, but operator controls around retry backpressure and dead-letter visibility remain incomplete.
- DAPR Workflow replay safety depends on SDK internals more than ideal. The current implementation has probes and deferrals, but future SDK upgrades need careful review.

Amelia (Developer): "Epic update required for Epic 10: no."

## Commitments

- Treat EventStore ingestion, handler diagnostics, and consistency-note behavior as public operational contracts.
- Keep EventStore integration package boundaries clean and adapter-based.
- Do not expose Server operational endpoints broadly until authN/authZ is addressed coherently.
- Keep DAPR topology claims backed by executable evidence or explicit deferrals.
- Keep natural-language embedding failures degraded, observable, and recoverable.
- Make known limitations visible in docs instead of burying them in story notes.
