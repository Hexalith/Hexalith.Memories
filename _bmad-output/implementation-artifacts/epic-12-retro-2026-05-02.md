## What Went Well

1. First-release evidence replaced assumptions.

   Story 12.1 reconciled the real `v1.2.0` release, verified NuGet and GitHub assets, applied branch protection, and created `docs/dev/release-runbook.md` from observed behavior.

2. The Epic 11 action list was actually executed.

   A1 branch protection, A2 `NUGET_API_KEY`, A3 tolerance checklist, A4 story file-scope enforcement, A5 baseline sweep, S11-FD partial-publish alerting, and S11-FA baseline resolution all landed through Epic 12 stories.

3. Silent-tolerance patterns became reviewable.

   `CONTRIBUTING.md` now names the failure-hiding idioms reviewers must challenge: suppressed command failures, missing-artifact tolerance, partial publish ambiguity, empty catches, zero-count passes, and default-empty inventories.

4. File scope moved from a principle to an executable check.

   Story 12.3 added a shared Python validator, local hooks, CI enforcement, and tests so story-scope leaks can fail before review rather than being discovered afterward.

5. Baseline accounting improved materially.

   Story 12.4 linked accepted release filters to deferred-work entries and strengthened `CiTestInventoryTests`. Story 12.6 removed the stale S11-FA filter and closed the deferred item after focused and release-lane validation passed.

6. Partial publish now has an operator-visible signal.

   Story 12.5 preserved the rerun self-healing behavior of `--skip-duplicate` while adding structured publish summaries, GitHub Actions annotations, step summaries, and GitHub Issue alerting.

## Challenges

1. Scope drift remained the recurring process risk.

   Several stories had to document or resolve submodule pointer drift or bundled cross-story work. The team handled the cases explicitly, but the pattern confirms why Story 12.3 was necessary.

2. Some review findings were process-hardening debt, not story blockers.

   Epic 12 correctly deferred CI edge cases, parser hardening, issue-alert race conditions, and release-runbook audit improvements instead of widening active stories until they lost their shape.

3. Validation was broad but still lane-specific.

   The curated release lane and focused suites were strong. Full-solution aggregate runs sometimes hit local runtime limits, so story notes had to distinguish validated lanes from broader local attempts.

4. The S11-FA root flake mode is dormant, not fully eliminated.

   Story 12.6 closed the stale filter correctly, but `12.6-RV5` still tracks the underlying fixed-tenant-id and capture-list hardening if the telemetry test flakes again.

5. Epic 13 began in parallel.

   Epic 13 was explicitly marked independent of Epic 12, but overlapping work made status reading noisier. The project needs to keep cross-epic dependency statements explicit.

## Team Agreements

- Keep story file scope as an executable contract, not a retrospective afterthought.
- Treat tolerance as suspect unless the story includes an idempotency proof, recovery path, or operator-visible signal.
- Do not keep release-lane filters without matching deferred-work entries and re-open triggers.
- Use observed release behavior as the documentation source of truth.
- Keep Epic 13 migration tooling operationally explicit: dry-run, live-run, resume, rollback, and failure states must be reviewable.
