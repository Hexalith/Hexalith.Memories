## What Went Well

1. Traversal became a first-class graph feature.
   Story 4.1 added `TraversalNode`, `TraversalEdgeInfo`, `TraversalResult`, `GraphTraversalService`, `BuildTraverseWithEdges`, and `GET /api/tenants/{tenantId}/traverse`. The response now carries node context and edge metadata in one call instead of forcing consumers to stitch IDs through another search round-trip.

2. Query construction stayed inside the safety boundary.
   Traversal and confidence queries were added through `IGraphQueryBuilder`. User-controlled values remain parameters, while edge labels are derived from the closed `EdgeType` enum. That kept the Cypher injection boundary consistent with the architecture.

3. Review closed real correctness gaps.
   Story 4.1 review hardened NFalkorDB edge collection parsing, stub or partial node parsing, case scoping, telemetry elapsed values, and annotation-count best-effort behavior. These were not cosmetic fixes; they protected behavior under realistic graph data.

4. Edge taxonomy made traversal usable.
   Story 4.2 introduced `EdgeTypeCategory` and `EdgeTypeTaxonomy`, defaulting traversal to semantic edges (`causedBy`, `correlatedWith`, `references`) and excluding structural edges (`contains`, `annotates`) unless explicitly requested. This reduced noisy traversal paths and preserved the distinction between causal and organizational relationships.

5. Structural edge behavior was made explicit.
   Story 4.2 clarified that `contains` traversal can use the Case hub to reach sibling memory units while still returning only memory units. Review patches made that behavior consistent for case-scoped paths and metadata collection.

6. Missing data became visible.
   Story 4.3 added `TraversalGapMarker` and classified stub nodes as explicit gaps instead of silently skipping them. This directly supports the product promise that incomplete causal chains must be traceable.

7. Confidence promotion shipped with audit fields.
   Story 4.3 added `ConfidencePromotionRequest`, `ConfidencePromotionResult`, `verifiedBy`, and `previousConfidence`, plus `PATCH /api/tenants/{tenantId}/edges/confidence`. Human verification can now improve edge confidence without changing the original edge origin.

8. Test coverage followed the risk.
   Epic 4 added contract serialization, query-builder, service, endpoint, and FalkorDB integration tests across traversal shape, default semantic filtering, structural edge traversal, invalid edge types, gap detection, retroactive gap resolution, and confidence promotion.

## Challenges

1. Graph driver result shapes were more fragile than the happy path implied.
   Story 4.1 had to make edge parsing defensive because FalkorDB `collect()` results can vary by driver shape and numeric representation. This is a recurring risk when Cypher maps cross a .NET driver boundary.

2. Case scoping was easy to get subtly wrong.
   Traversal needed to ensure paths and returned edge metadata did not leak out-of-case nodes. Story 4.2 then had to allow intermediate Case nodes for explicit `contains` traversal without returning Case nodes as memory units.

3. Structural and semantic relationships needed product-level rules.
   `CONTAINS` and `ANNOTATES` are useful graph infrastructure, but including them in default causal traversal would pollute answers. The taxonomy decision was necessary product behavior, not just a backend optimization.

4. Stub detection depends on a compatibility bridge.
   Story 4.3 uses content absence and newer stub metadata behavior to classify gaps. `deferred-work.md` still says the content-absent fallback must remain until the stub backfill migration has run against production databases.

5. Confidence is still a single-register audit model.
   `previousConfidence` records the immediately prior value, not a full history of promotions. That is acceptable for the current product surface, but it should not be mistaken for a complete audit log.

6. Some causal-chain evidence remains deferred to broader integration topology.
   `deferred-work.md` still tracks out-of-order EventStore integration coverage, correlation-root edge tests, explicit stub marker tests, and traversal primary-path improvements. Epic 4 has strong local coverage, but not every end-to-end causal ingestion scenario is closed.

## Key Lessons

1. Traversal needs full context, not just reachable IDs.
   The product experience depends on returning content snippets, timestamps, edge type, edge confidence, edge origin, and direction in one response. Otherwise every consumer has to reconstruct the story manually.

2. Semantic defaults are a product safety feature.
   Default traversal across all edges makes causal explanations noisy and potentially misleading. Excluding structural edges by default keeps the graph answer aligned with the user's "why" question.

3. Gap markers are part of correctness.
   Missing intermediate nodes are not absence of information; they are information. Making them explicit gives operators and developers a way to distinguish complete chains from partial chains.

4. Case scoping must be tested at the path and metadata levels.
   It is not enough for returned nodes to be case-scoped if the edge metadata can still reference out-of-case nodes. Both surfaces are part of the contract.

5. Human verification should preserve provenance.
   Confidence promotion updates confidence, but it should not rewrite inferred versus explicit origin. `verifiedBy` and `previousConfidence` maintain that distinction.

6. Integration topology remains the hardest causal proof.
   Unit and FalkorDB tests can prove graph behavior, but the full causal promise also depends on DAPR pub/sub ordering, EventStore metadata, ingestion idempotency, and late-arrival backfill.

## Epic 5 Preparation And Continuity

Epic 5, "Tenant Isolation & Multi-Tenancy," builds directly on Epic 4's graph traversal surface. It must prove that tenant scoping is enforced across RediSearch, Redis Vector, FalkorDB, ingestion, search, and traversal.

Epic 5 dependencies from Epic 4:

- `GraphTraversalService` must always execute against the tenant's dedicated FalkorDB database.
- `IGraphQueryBuilder` must remain the only graph query construction path.
- Traversal case scoping must not allow returned nodes or edge metadata to reference another case or tenant.
- `edgeTypes` filtering must remain deterministic so tenant isolation checks can reason about graph paths.
- Gap markers must not reveal data from another tenant when edge IDs collide or malformed tenant IDs are used.
- Confidence promotion must be tenant-scoped and should not update edges outside the requested tenant graph.

## Significant Discovery

Epic update required: yes, for Epic 5 readiness and follow-up planning.

Epic 4 did not invalidate Epic 5's direction. It sharpened what Epic 5 must verify. Tenant isolation is not just index naming; it includes graph traversal paths, edge metadata, gap marker visibility, confidence promotion writes, and deleting-state behavior.

Significant changes to carry into Epic 5:

1. Graph isolation tests must verify both returned traversal nodes and edge metadata.
   Impact: a traversal could appear isolated at the node list while still leaking connected IDs through metadata.

2. Confidence promotion is a graph write path and must be included in tenant enforcement analysis.
   Impact: Epic 5 should not only test search and traversal reads; it should also prove tenant-scoped edge updates.

3. Stub and gap marker behavior must be tenant-safe.
   Impact: missing-node identifiers are still information. A gap marker from the wrong tenant would be a leakage bug even if the full node is not returned.

4. Memories Server authN/authZ remains unresolved.
   Impact: Epic 5 can prove direct tenant-ID isolation, but external tenant-claim enforcement depends on the cross-cutting auth retrofit tracked in deferred work.

Recommended planning updates:

1. Add Epic 5 acceptance coverage for traversal edge metadata isolation.
2. Add a tenant-scoped confidence promotion negative test.
3. Add malformed or swapped tenant ID tests for traversal and confidence promotion.
4. Carry `TENANT_DELETING` validation into both ingestion and graph write paths.
5. Decide whether Memories Server authN/authZ is part of Epic 5 scope or an explicit prerequisite follow-up.

## Team Agreements

- Treat traversal responses as security-sensitive because edge metadata and gap markers can reveal relationships.
- Keep graph query construction behind `IGraphQueryBuilder`; no raw Cypher construction in endpoint or service code.
- Preserve the semantic-versus-structural edge distinction in default traversal behavior.
- Do not treat confidence promotion as a read-only feature; it is a graph write path and needs tenant-scope validation.
- Keep gap markers explicit, but validate that they never leak another tenant's identifiers.
