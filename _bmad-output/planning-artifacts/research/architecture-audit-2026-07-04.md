# Hexalith.Memories — Architecture, Performance & Readiness Audit

**Date:** 2026-07-04
**Method:** Six parallel read-only subsystem audits (Server host/API, ingestion pipeline, retrieval/graph, storage/tenancy/migration, contracts/clients/CLI/MCP/Web, tests/docs/deploy/CI) plus a structural pass over the solution topology. All findings are grounded in file:line evidence in the repository at commit `331cf10`.
**Purpose:** Evidence base for Sprint Change Proposal 2026-07-04 (Audit Remediation). Finding IDs `A1`–`A51` are referenced by the proposal's epic/story coverage map.

---

## Executive summary

1. The entire HTTP API is unauthenticated (46 endpoints, deferral acknowledged at `Program.cs:3122`); tenant identity is caller-asserted and the audit user comes from a spoofable `x-user-id` header.
2. The system is not event-sourced despite Hexalith conventions; domain state is direct-mutated Redis + FalkorDB via unguarded triple-writes with no outbox, and the consistency subsystem exists to detect divergence it cannot prevent.
3. NL vector keys (`{t}:vec:nl:`) nest inside the raw vector prefix (`{t}:vec:`), producing phantom consistency discrepancies, double-indexed KNN results, and a crash that fails entire tenant repair runs (independently confirmed by two audits).
4. Embedding vector migration is destructive (drops indexes before generating replacements), its rollback is a stub that always errors, and its write-block marker has no TTL or ownership lock.
5. `Program.cs` is a 3,836-line god file (43 of 46 endpoints inline; the search lambda alone is ~750 lines); the `Hexalith.Memories.Redis` project that should own store coupling is a placeholder.
6. RAG-quality ceilings: no chunking, no query-embedding cache, semantic pagination ignores `Offset`, fusion mixes uncalibrated score scales on an unpinned scorer and drops `CaseId`.
7. Scalability limits: content+vectors persisted 6–8× into workflow history per document, 3 serialized actor round-trips per embedding call, O(n²) patterns in directory batches / isolation verification / graph-scoped search, unbounded graph traversals that outlive the client timeout.
8. Observability stops at the workflow boundary (no trace propagation into activities); metric naming is split across two conventions; no dashboards committed; audit events miss tenant lifecycle, case membership, and deletions.
9. Operational readiness gaps: no Dockerfile/K8s/Helm/compose anywhere, no restore/import for the existing export, no backup/DR/capacity/incident runbooks, no coverage gating, 28 of 29 `[RunnableSkippedFact]` integration tests are empty stubs, and the migration subsystem has one test file.
10. Systemic duplication: routes ×2 (server 60 / client 23 literals), error envelopes ×118, CLI JSON formatters ×14, Redis key literals at ≥12 sites bypassing the declared single source of truth, two divergent RediSearch escapers, MCP tool skeleton ×4.

**Strengths to preserve:** health-check depth (real container/sidecar failure tests), the reflection-sweep contract serialization test, Testcontainers + full-Aspire fixtures asserting state-store end-state, the ingestion compensation/failed-units skeleton, `CliCommandExecutor` centralization, MCP reuse of `MemoriesClient` over Dapr invoke, `ExportWriter` streaming design, disciplined secrets handling.

## Open questions

1. Is this repo intentionally a platform/host repo exempt from the Hexalith domain-centric two-line-host rule? Not documented anywhere.
2. Is the direct-write (non-event-sourced) design deliberate or transitional? The `EventStore` project name and the consistency-repair investment suggest event sourcing was intended.
3. What is the assumed production trust boundary (gateway-terminated auth vs in-process)? Comments assume sidecar tokens + network isolation; nothing in-repo deploys or documents a gateway.
4. Is multi-replica deployment planned? Process-local caches and static config snapshots silently assume a single instance.
5. Scale targets (tenants, corpus per tenant) — these set the real severity of the O(n²) verifier, export scans, and the 100-result hybrid ceiling.
6. Is `Hexalith.Memories.Web` awaiting a FrontComposer host in another repo?
