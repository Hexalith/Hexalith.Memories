# Independent cross-component review · 20 November 2026

**Verdict.** The amended decisions pass the cross-component review. H1, H2, M2, M3, M4 and M7 have enforceable design outcomes.

Initial review of the working-tree spine at SHA-256 `89106ca99d87f6f708bbaa0939c20279a9b1d1352f84bf78918281dce038f6a2` found one remaining recovery case. The review traced the contracts and checked existing score and pagination source. Runtime fault injection and cross-surface qualification remain implementation work. | H1 · Projection target and coordinator | After a loss, let all three old successes arrive, then deliver an old write after the replacement fence is installed. **Coordinator state loss.** AD-2 rebuilds lost coordination state through replay. If a Dapr checkpoint disappears or rolls back, reconstructing the same source and attempt numbers could make an already queued success look current. Target fence recovery excludes late writes but cannot invalidate an acknowledgement already in transit. AD-3 needs an unambiguous recovery rule for a checkpoint whose prior issuance history cannot be proved, including joint target and checkpoint loss. The recovery case must prevent identifier reuse before fresh acknowledgements can count.

**Retest at SHA-256 `3c7bf368360f37c4d77d15ed9e9ee402660e767bbb9fbe85203f813215999f0e`.** AD-3 now allows initialization as new only with evidence of store and generation continuity. Erase both the target fence and coordinator checkpoint and deliver three successes from the lost attempt. Counting stops. Same-generation recovery requires an upper bound on every issued revision, including work in flight, followed by an empty acknowledgement set at a higher revision. Without that bound, authoritative replay uses a never-reused schema/epoch pair. Old confirmations match neither valid recovery path. The ledger explicitly requires this joint-loss case. The other five reviewed outcomes still hold. No open design finding remains in this lens.
