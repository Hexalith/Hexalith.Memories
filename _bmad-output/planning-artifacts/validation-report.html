Decision-readiness

thin

A March decision-maker could have acted: proof-of-thesis before integration surfaces, physical isolation and cases from day one, fusion as a dedicated spike, MCP as a 4-week fast-follow, and a graph-axis fallback. Those are stated as decisions, not considerations.

What a decision-maker cannot do now is execute the ship checklist without choosing which layer of the document is authoritative. The body has been patched toward implementation (RRF, Google-only embeddings, OpenBao, published packages, TenantProvisioningWorkflow) while the gates, hero journey, and resource line still describe the March greenfield bet. There are zero Open Questions, [ASSUMPTION] tags, or [NOTE FOR PM] callouts; remaining tensions were edited into coexistence rather than left visible.

Adversarial review

_bmad-output/planning-artifacts/review-adversarial-general.md

Refuse to sign this PRD as a go/no-go instrument. The core bet is declared with a kill switch that cannot fail as written, an MVP that never touches the product's advertised causal/zero-code/MCP story, and a Greenfield classification that already inventories nine published NuGet packages. The document is excellent at sounding decisive — 80%, hard gates, physical isolation, zero mapping code — and systematically unwilling to specify the comparisons, edge sources, identity model, or relevance protocol that would make those words expensive. A skeptical engineer would treat it as a positioning memo stapled to an in-flight codebase, not as a decision artifact.

critical

The 80% hybrid kill switch is unfalsifiable as specified

Success Criteria § Measurable Outcomes; Innovation § Validation Approach; FR25; NFR24–NFR26
The protocol selects 5–10 queries that require all three axes, scores hybrid vs each single axis with NDCG@10, calls 80% a hard line, and never defines a delta, a corpus, a graded-relevance scale, or a two-axis control. Queries requiring all three axes are constructed so hybrid then wins by construction. The industry baseline — BM25+vector — is never the control.
Fix: Frozen corpus and realistic (not graph-filtered) queries; graded labels after queries exist; primary comparison hybrid vs BM25+semantic; pre-registered ΔNDCG and N; named kill actions. Delete the unlabeled A/B fallback.
critical

MVP proves a retrieval toy, not the product thesis

Executive Summary; § MVP Feature Set; Phase 1.5; Journey 1; MVP Go/No-Go Gate
The product is sold as a causal memory server for LLM agents with zero-code EventStore indexing; Phase 1 is CLI ingest/search on files. You can pass every hard gate and still have proven none of: agents getting better answers, CausationId becoming a queryable story, or dotnet add package auto-indexing an event stream.
Fix: State that thesis MVP proves the algorithm only, then either demote EventStore/MCP/causal narrative from the exec summary until Phase 1.5, or put one of them on the hard-gate list. Make Phase 1.5 slip a product delay, not an MVP scope accordion.
critical

Phase 1 has no honest graph to fuse

MVP Feature Set #3–#4; Causal Intelligence; FR16–FR17, FR33, FR46–FR50; Journey 9
Hybrid fusion is the thesis and an MVP hard gate, but the edges that make a graph axis more than a folder tree (caused_by, correlated_with) are EventStore metadata scheduled for Phase 1.5. File ingest never specifies how non-trivial edges appear. Implementers will invent an edge story to make the benchmark pass.
Fix: Closed Phase 1 edge inventory. If causal edges are absent, forbid three-axis until EventStore lands; validate BM25 vs vector vs BM25+vector in Phase 1. Remove DAPR event publish from Journey 9 or move it to 1.5.
critical

Fix: Reclassify as brownfield / in-progress. Add a status column on every FR/NFR: shipped, partial, not started. Split current topology we must not break from net-new MVP remaining work.
